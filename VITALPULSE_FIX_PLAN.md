## Cross-account name leakage (user-reported, off-plan, 2026-07-23)
- [x] Root cause: `vitalpulse_user` in `localStorage` is a single shared key for the whole browser origin, and Firebase Auth's session is *also* shared across every tab of that browser (not per-tab). Logging into a second account in another tab silently overwrites both for every already-open tab. The existing "fix" for this (`main.js`, page-load sync block) re-fetched a profile using the *cached* uid instead of checking who was actually signed in — so it just re-confirmed whichever account's data was already sitting in the cache instead of catching the mismatch. No page ever verified that the signed-in account's role actually matched the dashboard it was viewing.
- [x] Fix: added `waitForAuthUser()` and `fetchVerifiedUser()` to `src/auth.js`, which check the *live* Firebase Auth state (not the localStorage cache) and look up that uid's real role. `main.js`'s dashboard bootstrap now uses this to compare the live account's role against the current page (admin.html/hospital.html/donor.html) and redirects to the correct dashboard on mismatch, instead of silently rendering whichever name happened to be cached.
- Note: this doesn't enable *simultaneous* multi-role sessions in one browser — that's not how Firebase Auth works (one session per browser, shared across tabs by design). What it fixes is the silent wrong-data display; a genuinely stale/mismatched tab now self-corrects (redirects) within about a second instead of staying wrong indefinitely. To view multiple roles at once, use separate browsers/profiles/incognito windows, one per role.
